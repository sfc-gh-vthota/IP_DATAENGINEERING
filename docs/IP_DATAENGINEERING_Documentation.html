1. Architecture Overview

This project implements a Medallion Architecture (Raw → Stage) with metadata-driven SCD processing. The RAW layer receives full-refresh data from source systems daily. A single generic stored procedure reads transformation SQL from a metadata table, creates an intermediate (ID) table, and performs a MERGE into the STAGE layer using either SCD Type 1 (overwrite) or SCD Type 2 (history tracking).

6. Stored Procedures

SP_LOAD_STAGE(P_STAGE_TABLE_NAME VARCHAR)

The core generic procedure. Called once per stage table. Performs all 4 steps dynamically:

  1. Read Config — Queries ETL_CONFIG for the source SQL, PK columns, and SCD type.
  2. Create ID Table — Runs CREATE OR REPLACE TABLE {table}_ID AS {SOURCE_SQL}. This intermediate table has only business columns.
  3. MERGE/Load — Dynamically builds a MERGE statement using INFORMATION_SCHEMA.COLUMNS to discover columns. Handles Type 1 (upsert) and Type 2 (expire + insert) differently.
  4. Cleanup — Drops the ID table and temporary metadata tables.
-- Usage (single table):
CALL IP_DATAENGINEERING.METADATA.SP_LOAD_STAGE('STG_SERVER_SUMMARY');

-- Returns: 'ID table created. SCD Type 1 MERGE completed. ID table dropped.'

SP_RUN_ALL_STAGE_LOADS()

Orchestrator that loops through all IS_ACTIVE = TRUE rows in ETL_CONFIG and calls SP_LOAD_STAGE for each:

-- Run all active stage table loads:
CALL IP_DATAENGINEERING.METADATA.SP_RUN_ALL_STAGE_LOADS();

-- Returns status for each table:
-- STG_SERVER_SUMMARY => ID table created. SCD Type 1 MERGE completed. ID table dropped.
-- STG_INFRA_ASSETS => ID table created. SCD Type 2 completed. ID table dropped.
-- STG_INCIDENT_DETAIL => ID table created. SCD Type 1 MERGE completed. ID table dropped.

7. SCD Type 1 vs Type 2 Logic

SCD Type 1 (Overwrite)

Used for STG_SERVER_SUMMARY and STG_INCIDENT_DETAIL. No history is kept.

flowchart LR
  ID["ID Table\n(new data)"] --> M{"MERGE\non PK"}
  M -->|"Match + Changed"| U["UPDATE row\nDW_UPDATE_DTS = now"]
  M -->|"Match + Same"| S["Skip\n(no change)"]
  M -->|"No Match"| I["INSERT row\nDW_INSERT_DTS = now\nDW_UPDATE_DTS = now"]

SCD Type 2 (History Tracking)

Used for STG_INFRA_ASSETS. Old versions are preserved with an expiration timestamp.

flowchart LR
  ID2["ID Table\n(new data)"] --> CHK{"Change\nDetected?"}
  CHK -->|"Yes"| EXP["EXPIRE old row\nDW_ACTIVE_FLAG = N\nDW_END_DTS = now"]
  EXP --> INS["INSERT new version\nDW_ACTIVE_FLAG = Y\nDW_START_DTS = now\nDW_END_DTS = 9999-12-31"]
  CHK -->|"No"| SKIP2["Skip\n(no change)"]
  ID2 --> NEW{"New\nRecord?"}
  NEW -->|"Yes"| INS
  NEW -->|"No"| CHK
Change Detection
The procedure compares every non-PK business column between the ID table and the stage table using NVL(CAST(TGT.col AS VARCHAR), '~~NULL~~') != NVL(CAST(SRC.col AS VARCHAR), '~~NULL~~'). This handles NULL values correctly and works across all data types.

8. How to Add a New Stage Table

1Write the Source SQL

Write a SELECT that joins the necessary RAW tables. Test it standalone first.

2Create the Target Table

Create the table in STAGE schema with the same columns as your SELECT, plus the DW_* metadata columns. For Type 1: add DW_INSERT_DTS and DW_UPDATE_DTS. For Type 2: also add DW_ACTIVE_FLAG, DW_START_DTS, DW_END_DTS.

3Insert Config Row 
INSERT INTO IP_DATAENGINEERING.METADATA.ETL_CONFIG
  (STAGE_TABLE_NAME, SOURCE_SQL, PRIMARY_KEY_COLUMNS, SCD_TYPE)
VALUES
  ('STG_YOUR_TABLE', 'SELECT ... FROM ...', 'YOUR_PK_COL', 2);
4Run the Load 
CALL IP_DATAENGINEERING.METADATA.SP_LOAD_STAGE('STG_YOUR_TABLE');

Or it will be picked up automatically by SP_RUN_ALL_STAGE_LOADS().

Part E: Demonstrate SCD Type 1 (Overwrite)

7Show Current State of a Server 
SELECT SERVER_ID, SERVER_NAME, OS_NAME, OS_VERSION, RAM_GB,
       DW_INSERT_DTS, DW_UPDATE_DTS
FROM STAGE.STG_SERVER_SUMMARY
WHERE SERVER_ID = 'SRV-0010';

Note the DW_INSERT_DTS and DW_UPDATE_DTS are the same (row was never updated since initial load).

8Simulate a Source Change 
-- Source system upgraded the OS
UPDATE RAW.SERVERS SET OS_VERSION = '24.04', RAM_GB = 128
WHERE SERVER_ID = 'SRV-0010';

Talk about: "The source system pushed an update — the server got a new OS version and more RAM. In a real scenario, this would happen through the daily full refresh. Let's run the load."

9Reload and Verify Type 1 
CALL METADATA.SP_LOAD_STAGE('STG_SERVER_SUMMARY');

SELECT SERVER_ID, SERVER_NAME, OS_NAME, OS_VERSION, RAM_GB,
       DW_INSERT_DTS, DW_UPDATE_DTS,
       CASE WHEN DW_UPDATE_DTS > DW_INSERT_DTS THEN 'UPDATED' ELSE 'ORIGINAL' END AS STATUS
FROM STAGE.STG_SERVER_SUMMARY
WHERE SERVER_ID = 'SRV-0010';

Talk about: "SCD Type 1 overwrites in place. The row now shows the new OS version and RAM, the DW_UPDATE_DTS moved forward, but the DW_INSERT_DTS is still the original insert time. There is only ONE row — no history kept."

Part F: Demonstrate SCD Type 2 (History Tracking)

10Show Current State of a Network Device 
SELECT DEVICE_ID, DEVICE_NAME, FIRMWARE_VER, DEVICE_STATUS,
       DW_ACTIVE_FLAG, DW_START_DTS, DW_END_DTS
FROM STAGE.STG_INFRA_ASSETS
WHERE DEVICE_ID = 'NET-0015';

Note: Single row with DW_ACTIVE_FLAG = Y and DW_END_DTS = 9999-12-31.

11Simulate a Device Change 
-- Device firmware updated, status changed
UPDATE RAW.NETWORK_DEVICES
SET FIRMWARE_VER = 'v20.0.0', DEVICE_STATUS = 'MAINTENANCE'
WHERE DEVICE_ID = 'NET-0015';
12Reload and Verify Type 2 
CALL METADATA.SP_LOAD_STAGE('STG_INFRA_ASSETS');

SELECT DEVICE_ID, DEVICE_NAME, FIRMWARE_VER, DEVICE_STATUS,
       DW_ACTIVE_FLAG, DW_START_DTS, DW_END_DTS
FROM STAGE.STG_INFRA_ASSETS
WHERE DEVICE_ID = 'NET-0015'
ORDER BY DW_START_DTS;

Talk about: "SCD Type 2 preserves history. Now we have TWO rows:
• The old row is expired: DW_ACTIVE_FLAG = N, DW_END_DTS shows when it was superseded.
• The new row is active: DW_ACTIVE_FLAG = Y, DW_END_DTS = 9999-12-31.
We can always query the full change history for audit or compliance, and the active view just filters on DW_ACTIVE_FLAG = 'Y'."

Part G: Show Idempotency

13Re-run With No Changes 
-- Record current timestamps
SELECT MAX(DW_UPDATE_DTS) AS BEFORE_TS FROM STAGE.STG_SERVER_SUMMARY;

-- Re-run
CALL METADATA.SP_LOAD_STAGE('STG_SERVER_SUMMARY');

-- Verify nothing changed
SELECT MAX(DW_UPDATE_DTS) AS AFTER_TS FROM STAGE.STG_SERVER_SUMMARY;

Talk about: "The procedure is idempotent. If nothing changed in the source, no rows are updated in the target. The timestamps are identical before and after. This means you can safely re-run the pipeline without side effects."

14Explain How to Add a New Table

Talk about: "To add a new stage table, the customer just does three things:

Part I: Wrap-Up Talking Points

Key Value Propositions
1. Metadata-Driven: All transformation logic lives in a config table, not in code. Easy to audit and change.
2. Generic Procedure: One stored procedure handles all tables. Reduces code duplication and maintenance.
3. Flexible SCD: Support both Type 1 and Type 2 per table, configurable via a single flag.
4. Idempotent: Safe to re-run. No duplicates, no unnecessary updates.
5. Auto-Discovery: The procedure reads column schemas dynamically from INFORMATION_SCHEMA. Adding columns to the source SQL and target table just works — no procedure changes.
6. Snowflake Native: Pure SQL stored procedures, no external tools or orchestrators. Can be scheduled with Snowflake Tasks.
